# TGTG Vienna Telegram Bot — full service

Бот по Too Good To Go: топ магазинов рядом по геолокации, топ по сети
магазинов по всей Вене (HOFER, SPAR, BIPA…), выбор километраж или время в
дороге, дом/работа/свои адреса, слежка за появлением товара. Всё хранится
в SQLite — юзеры, адреса, слежки, кэш Вены.

## Возможности

- **🗺️ Топ рядом** — кидаешь живую геолокацию, бот отвечает топом магазинов
  в радиусе (1/3/5/10 км): рейтинг, отзывы, расстояние, время, цена, наличие.
- **🏪 Сеть магазинов** — `/chain HOFER` (или кнопка) → лучшие по рейтингу
  магазины сети по всей Вене, с расстоянием/временем от твоей точки.
- **📍 Мои адреса** — дом (`/home`), работа (`/work`), свои места (`/places`).
  Задаются геолокацией или текстом (текст — только с Google-ключом).
- **⚙️ Настройки** — радиус, сортировка (рейтинг / отзывы / ближе /
  ⚖️ ценность = рейтинг на км или минуту), фильтр «от 100 отзывов»,
  режим **километры / время**, точка отсчёта (текущая / дом / работа).
- **🔔 Слежка** — кнопка на магазине; бот раз в минуту проверяет наличие и
  пишет, когда товар снова появился. Только уведомление: резервируешь сам.
- **🚏 Отправления** — `/departures Rochusgasse` (или кнопка с геолокацией)
  показывает, через сколько минут придёт U-Bahn/трамвай/автобус — реальное
  время Wiener Linien (OGD Echtzeitdaten, бесплатно, без ключа).

## Способы передвижения и адреса — бесплатно

**Платить не нужно.** В настройках выбирается способ передвижения, время
считается по реальным маршрутам для каждого:

- 🚗 **машина** — OSRM car (FOSSGIS, OpenStreetMap); с Google-ключом — пробки.
- 🚌 **транспорт** — ÖBB Scotty HAFAS (покрывает Wiener Linien/VOR, бесплатно, без ключа).
- 🚶 **пешком** — OSRM foot (FOSSGIS).
- 🚲 **вело** — OSRM bike (FOSSGIS).

Все маршруты кэшируются в БД на 6 ч. Если роутер не ответил — грубая
оценка по прямой для выбранного способа (помечается `≈`).

- **Адреса текстом** (дом/работа/места) — Nominatim (OpenStreetMap),
  бесплатный геокодер (не чаще 1 запроса/сек, бот это соблюдает).

Google остался как **опциональное** улучшение (учёт пробок + свой геокодер):
задать `GOOGLE_MAPS_API_KEY` в `.env` — тогда пробки и Google-геокодинг.
Если не задавать — всё выше работает само.

## Wiener Linien: отправления

`wl.py` + `wl_stops.json` (справочник 1811 остановок, собирается из CSV
`build_stops.py`) дают табло отправлений через бесплатный OGD-интерфейс
Wiener Linien:

```
GET https://www.wienerlinien.at/ogd_realtime/monitor?rbl=<id>&activateTrafficInfo=vo
```

`rbl` — это остановка+линия+направление; для станции берутся все её rbl и
отправления мержатся. Честная таблица по времени, 🟢 = реальное время, без
🟢 — по расписанию.

## Установка и запуск

```bash
cd tgtg_bot
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# токен уже в .env (или: TGTG_BOT_TOKEN=... python bot.py)
python bot.py
```

Токен бота — у @BotFather (`/newbot`).

## База данных

`tgtg_bot.db` (создаётся сама):
- `users` — telegram_id, дом/работа;
- `saved_places` — именованные места;
- `watches` — слежки (уведомления);
- `stores` — кэш скана Вены (~5 тыс. магазинов);
- `travel_times` — кэш Google Distance Matrix;
- `meta` — время последнего скана, отложенные запросы сетей.

Первичное наполнение кэша из уже снятого скана (иначе первый `/chain`
запустит живой скан ~3-5 мин):

```bash
.venv/bin/python seed_db.py ../vienna_items_all.json
```

Дальше бот сам пересканирует Вену, когда кэш устареет
(`TGTG_CHAIN_TTL_S`, по умолчанию 30 мин).

## Сессия TGTG

`session.json` — access/refresh token + `datadome`-cookie, снятые с реального
Android-приложения. Бот сам рефрешит токен (`POST /api/token/v1/refresh`,
TTL access-токена 48 ч). Если `datadome` протухнет и пойдут 403 — пересними
сессию в эмуляторе (см. корневой RUNBOOK) и перезапиши `session.json`.

## Важно

Бот **не резервирует и не оплачивает** мешки — только уведомляет о наличии.
Автоматическая покупка нарушает ToS Too Good To Go; скорость снайпера на
этапе обнаружения это сохраняет.

## Хостинг на Railway (бесплатный, 24/7)

Бот — это long-polling (не вешает свой порт), поэтому Railway по умолчанию
считает сервис «мёртвым» и перезапускает его. Файлы в этой папке это чинят:

- `railway.json` — startCommand, `healthcheckPath: /health`,
  `restartPolicyType: ON_FAILURE` (перезапуск только при падении).
- бот в `main()` поднимает мини-HTTP-сервер на `$PORT`, который отвечает
  `200` на `/health` — Railway видит живой сервис и не убивает его.
- `.python-version` — пинит Python 3.12 для Nixpacks.
- `.railwayignore` — не заливать `.venv`, локальную БД, `.env`.

### Как задеплоить

1. Создай проект на [railway.com](https://railway.com) → **New Service →
   Deploy from GitHub repo** (или `railway up` из этой папки через CLI).
2. В настройках сервиса укажи **Root Directory = `tgtg_bot`** (или заливай
   прямо эту папку).
3. Задай переменную окружения:
   ```
   TGTG_BOT_TOKEN=123456:ABC...   # твой токен от @BotFather
   ```
4. Убедись, что `session.json` **попал в деплой** (он в этой папке; если
   деплоишь из git — закоммить его). Это логин TGTG.
5. Deploy. Готово — бот работает 24/7.

### Персистентность (рекомендую для прода)

Контейнер Railway эфемерен: при каждом редеплое файловая система сбрасывается,
значит БД (юзеры, адреса, слежки) и обновлённая сессия теряются. Чтобы этого не
было — подключи том:

```bash
railway volume add -m /data
```

и задай переменные:

```
TGTG_DB_PATH=/data/tgtg_bot.db
TGTG_SESSION_PATH=/data/session.json
```

Тогда после первого старта один раз закинь сессию в том (это делается через
`railway run` или `railway volume shell`):

```bash
railway run "cat > /data/session.json" < session.json
```

Дальше бот сам рефрешит токен и пишет обратно в `/data` — переживает редеплои.



- `bot.py` — Telegram-часть (меню, кнопки, фоновые задачи).
- `tgtg_client.py` — клиент API TGTG: рефреш токена, гео-запрос, скан Вены сеткой, статус товара.
- `db.py` — SQLite-слой.
- `geo.py` — расстояние, Google время/геокод, score «ценность».
- `seed_db.py` — наполнить кэш из сохранённого скана.
- `.env` — токен бота (+ опц. Google-ключ).
